# 现成图纸接入

Codex，2026-10-26，v0.3.0。应用代码 AGPL-3.0，图纸内容的作者和许可单独记录。目前仅4张原创几何示例，未新增第三方角色图纸。

列表路由 `#library`，详情 `#library/flower`。支持关键词（名称、作者、分类、标签）、分类、最长边尺寸、色数上限组合检索，以及用豆数量排序。点击开始拼直接载入原始格子与色号，不对现成图纸再次图片取色。

在 `src/library.js` 的 patterns 数组增加记录（也可从单独数据文件导入后拼入该数组）：

```js
{
  id:'example-chart', name:'图纸名称', category:'植物', tags:['花朵','小图'],
  note:'图纸简介', width:2, height:2,
  author:'原图纸作者', source:{label:'作者提供的图纸',url:'https://example.com/original'},
  license:'填写实际内容使用许可或授权范围', permissionStatus:'ready',
  palette:'MARD', colorCodes:['H07','H02'], cells:[0,null,1,0]
}
```

- `cells` 按从上到下、从左到右展开，长度必须是 width × height；null 是不放豆，数字索引 colorCodes。白豆是实际色号，不是 null。
- 色号使用当前上游映射中的精确键（如 H02），不自动猜测相近色或跨品牌替换。颜色必须属于同一已支持的色板；当前运行只支持MARD参考版。
- `createCatalog` 校验ID、尺寸（1–128）、格子数量/颜色索引、来源字段及未知色号。未核对好的记录用 `permissionStatus:'pending'`，不会进入可用图库；ready表示已完成数据与来源使用范围核对，不是自动授权。
- 原创示例的 `colors` HEX 是历史画法，按参考色板映射；翻版图纸应使用 colorCodes 保持原号。不要把上游代码许可误当第三方图纸内容许可。
- 新图纸逐格转录后对照原图的尺寸、色号、各色数量和总颗数；核对作者、来源链接和使用范围后再标ready。保留原署名；不同许可内容不因放入源码包而自动变为AGPL。
- 详情页展示作者/来源/使用说明；现成图纸PNG导出带作者/来源行。后续精修仍保留来源，不能把精修当作来源消失。

本模块是本地静态内容库，无后台投稿、账号或云上传。用户提供图纸后由维护者整理数据再构建；当前不包含截图自动识别或OCR。新增数据需随实际对应源码包保留适用许可说明。

验证命令：`npm test`、`npm run build`、`npm run verify`。若已有预览服务，新增运行文件后需要重启，以更新静态资源白名单。


## 2026-10-27 独立文件与本地草稿（Codex）

当前默认构建仍为4张原创图：`scripts/catalog-build.mjs` 生成 `/catalog/index.json` 摘要索引、`/catalog/charts/{id}.json`、`/catalog/thumbs/{id}.png`。索引条目含名称、分类、系列、别名、标签、尺寸/颗数/色数、作者来源、许可、status、unknownCount及两条资源路径，不含grid/cells/runs/materials。

单图schema=1，id/宽高必须与索引一致；colorCodes是MARD精确键。encoding=flat时cells按行展开，null留空、0起色号索引；encoding=rle时runs是`[重复次数,索引或null]`，整图连续展开，解码严格限制128×128，数量和摘要必须匹配。内部本地草稿才允许-1未知；未知格保留?和洋红填色，不能当null，不进入制作。

`catalog-store` 仅在查看详情/开始拼时读取单个数据文件，合并同图并发读取、失败移除缓存以支持重试，LRU最多12份。`catalog-view` 在摘要上全库组合检索名称/别名/角色系列/分类/标签/作者及数值筛选；超过24张时每页24张，小库每页6张。列表用独立img缩略图，不在DOM逐豆生成SVG。中文角色名、英文名、无声调全拼（条目已录入的别名）可检索，未实现任意中文自动拼音转换。

显式本地草稿流程：`node scripts/prepare-local-catalog.mjs` → `npm run build -- --local-catalog`。输入来自本机docs研究目录并生成被忽略的`.local-catalog/`，索引localPreview=true，status=draft，不更改来源许可。6张PNG由先前草稿数据绘制，未知格与JSON一致。默认构建不含它们；发布打包检测localPreview=true会退出，防止把本地草稿误当正式图库。网站和源码包公开构建仍可从4张原创资料复现。

批量OCR/审核工具和万图性能验证仍未完成；当前六图身份、原帖来源和逐格内容交由独立DeepSeek会话审核，不能把能够解码当作审核通过。

本轮DeepSeek已完成独立审核并回传：本地接入层采用第2图19格F04→F05确定修正（原研究输入不改），未知19格仍保留。catalog-image.mjs为全部条目从当前解码数据生成160px无损PNG，白豆有alpha、空格透明，故换码修正会同步影响缩略图。审核覆盖范围与未核项见本地审核目录，草稿并未升级为公开ready。

## 批量草稿导入（Codex，2026-10-27）

已增加任意项目内批次目录的显式导入，目录提供 `index.json` 和索引所指的单图 JSON。每图先使用网站同一个解码器校验，全部通过后再写本地库；`--check` 只校验，不写入：

```powershell
node scripts/prepare-local-catalog.mjs --batch docs/batch-gen1-2026-10-27/translation-final --check
node scripts/prepare-local-catalog.mjs --batch docs/batch-gen1-2026-10-27/translation-final
npm run build -- --local-catalog
```

要求索引 `localPreview:true`、每条 `status:draft`，保留来源和未知格。缩略图从导入后的格子数据重新生成，不使用原截图缩小，因此不会残留水印、坐标或旧色号。新批次替换本地索引；上批未引用的文件即使仍在磁盘，也不会进入构建清单。重启本项目预览服务后才能读取新增文件。

本机第一世代批次的原件、SHA256清单、识别候选、坐标重绘和独立审核证据保留在被Git忽略的 `docs/batch-gen1-2026-10-27/`，不进入站点或源码ZIP。完整MARD主色表保持291色，数据按原图印刷色号记录，不使用最近RGB颜色猜码。同一填色出现不同标签时逐格覆盖；白豆与空白分开，印刷缺损则保留未知。

批次工具目前针对本次网格版式，含显式几何校正和人工/AI审核，并非任意截图全自动导入器。结构检查、代表字形审核、整图轮廓检查、每格印刷标签全量审核是不同覆盖范围；批次质量文件必须分别说明，不能将解码通过当作图纸完全准确。大量图纸的性能已可按151张批次验证，万图级压力测试仍未做。

## 本地人工校对后台（Codex，2026-10-27）

完成本地草稿构建后，显式开启后台：

```powershell
node scripts/serve.mjs --dist --port 3045 --local-review docs/batch-gen1-2026-10-27/translation-final
```

入口 `http://127.0.0.1:3045/__review/`；草稿详情也有“对照原图 / 补色号”。可按名称/编号查找全部151张或仅待确认图，原JPEG与数据图同步定位，原图完整查看、3×3邻格最近邻像素放大、连续滚轮缩放、MARD291色号填写、补豆/留空/待确认、显式保存、撤回上次保存。

后台读取冻结批次的 `index.json`、`batch-manifest.json` 和上一级 `inventory.json`；原图只通过清单ID访问，每次核验SHA256，不接受客户端文件路径。只监听127.0.0.1，默认未带 `--local-review` 时原图、后台、API均404；修改请求需要精确Host/Origin和当前会话令牌。此功能是本机维护工具，不是已上线的多人账号后台。

人工记录唯一持久化正本为被Git忽略的 `.local-review/state.json`，含批次指纹、每格修改前后值和历史。原图、冻结识别结果及审核JSON不修改。保存后派生更新 `.local-catalog/` 与 `dist/catalog/` 的单图JSON、PNG及索引用量；服务重启会从人工记录重建派生文件。图纸仍为draft，不自动改来源许可或公开发布。

后续构建用 `npm run build -- --local-catalog` 会保留已保存的 `.local-catalog` 人工修改。再次运行批次导入会恢复机器稿的派生数据；如需这样做，先保留 `.local-review/state.json`，再以同一批次开启后台恢复人工记录。人工记录与新批次指纹不一致时拒绝静默套用，需显式核对迁移。浏览器中未点击保存的修改只在该页内，刷新前会提示，保存后才能跨刷新保留。多人、跨设备同步与最终人工版ZIP再导出尚未实现；原批次ZIP仍是冻结机器稿。

## 系列、类型与合集（Codex，2026-10-27）

图纸的归属按 `category → series → section → collection` 记录，`collectionId`标识具体合集。例如当前151张统一为：动漫游戏 → 宝可梦 → 图鉴 → 第一代宝可梦图鉴 · 151只（ID `pokemon-gen1-pokedex`）。合集不是整个宝可梦系列，也不是“全部第一代相关作品”的集合。

页面提供级联的系列/类型/合集筛选；选择合集会带出父级，切换系列或大类会清理不兼容筛选。摘要、卡片、详情展示合集，名称/编号检索可与合集、尺寸、色数组合使用。筛选项和数量从已接入资料生成，不显示尚未导入的空合集。

后续按实际资料分别建合集，例如：宝可梦/图鉴/第二代图鉴；宝可梦/地区形态/阿罗拉形态；宝可梦/特殊形态/超级进化（Mega）或超极巨化；宝可梦/主题合集/精灵球、皮卡丘、伊布；其他IP/角色合集/具体套图。这些仅是用户提供目录对应的分组示例，本轮没有导入其图纸。不同主题、造型、版本不因为角色同属宝可梦就并进第一代图鉴。

新批次摘要显式提供：

```js
{ category:'动漫游戏', series:'宝可梦', section:'地区形态',
  collection:'阿罗拉形态', collectionId:'pokemon-alola-forms' }
```

合集字段可选以兼容旧目录；一旦填写合集，需要同时有系列、类型与名称。未显式填写ID时从父级和名称生成稳定标识。当前冻结第一代批次通过`classifyCatalogEntry`的严格来源标签兼容规则添加分类，不修改冻结索引或人工记录的批次指纹。构建时生成分类摘要，网页读取时同样规范化，旧本地校对服务保存派生索引后也不会丢失归类。原图JSON位置数据、人工保存的色号和来源许可均不改变。

## 左右镜像（Codex，2026-10-27）

工坊“图纸工具”新增小按钮“↔ 镜像”，每次点击左右翻转整张当前图纸。逐行逆序保存真实格子数据，保持尺寸、品牌、色号、空格/白豆和总用量；不反转色号文字或坐标数字。支持现有撤销历史，连点两次恢复原图；之后的PNG/CSV导出跟随当前图纸。参数待重新生成或正在处理时按钮禁用，避免覆盖未生成参数。镜像属于当前制作图的编辑，不自动覆盖图库原件或后台人工校对记录。

## 用户确认的线上/线下分工（2026-10-27）

人工校对台永久作为本机维护工具使用；正式站点发布校对后的数据和缩略图，不部署原图、人工日志、校对页面/API或相关操作入口。用户明确表示一轮校对完成后，已授权按GitHub→正式部署顺序上线该轮确认内容，无需再重复询问。

正式发布时以已保存的人工版本生成独立发布快照，核对数据与缩略图、用量及分类一致；冻结机器稿只作对照，不能重新导入覆盖人工结果。unknownCount=0仅是数据状态，不替代用户对整批“校对完成”的明确声明。

当前构建/发布隔离维持原状：默认4张原创；本地155张版本仍为localPreview，发布脚本会拒绝。校对完成后的正式目录转换与实际部署在用户发出完成信号时执行，本次约定没有触发上线。

## 最新流程：先发布、持续校对、保存后同步（2026-10-27）

用户最新要求已取代“等整批校对完成再发布”。当前已保存版可先发布；本机后台新增按原色号→目标MARD色号批量替换，影响格数可见，先预览再保存，保存作为一条人工修订且可撤回。最多支持128×128整图修改，空格不参与换色。

公开图纸从已保存版本规范化为catalog-content/，状态ready仅表示可公开使用且没有未知格，不代表原帖权利或每个印字都已全量验证。公开提示AI辅助转译的误差边界和来源待补信息。原始截图与人工历史不上传。前6张公开ID规范为pokemon-kanto-001至006，线下旧ID继续使用。

带--auto-publish启动校对服务后，保存/撤回触发同步队列；多次保存合并成最新快照，同内容不发布。未知图保留旧公开版本，网络失败不会丢失本地修改。网站按内容版本读缓存，每30秒在活动图库检查更新；工坊中正在编辑的图不被自动替换。

## 撤销与重做（Codex，2026-10-27）

人工校对顶部“撤销编辑 / 重做编辑”作用于当前图纸未保存的单格、批量编辑，最多50步，按图纸独立保留；修改仍需显式保存。保存后开始新的预览历史。底部“撤回上次保存 / 重做保存”支持最多50条已保存修订，刷新或重启后保留，每次实际改变都记入人工日志并触发原有图纸同步。新保存清空重做分支，旧版单步撤回记录会按日志兼容重建；409版本冲突及原图哈希检查不变。

工坊提供撤销和重做，最多20步；镜像、画笔/橡皮整段笔画及品牌换号均保留图格与品牌快照。新编辑、加载另一张图或重新生成会清空相应重做分支；双指手势取消未完成笔画时恢复手势前历史。Ctrl/Cmd+Z撤销，Ctrl/Cmd+Shift+Z或Ctrl/Cmd+Y重做，输入框内保留原生文字撤销行为。
